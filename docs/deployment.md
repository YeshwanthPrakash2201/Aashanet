# Deploying AASHANet AI

This guide puts the backend and database on the internet so the phone app
works anywhere, not only on the same Wi-Fi as your PC. Everything here uses
free plans:

| Part | Service | What it runs |
|---|---|---|
| Database | [Neon](https://neon.tech) | PostgreSQL |
| Backend | [Render](https://render.com) | FastAPI (`backend/`), set up by `render.yaml` |
| Phone app | your phone | release APK built with Flutter |

Follow the parts in order. Total time: about 30–45 minutes.

> **Secrets:** your Gemini key, database password and JWT secret are typed
> into the Neon/Render dashboards only. Never put them in a file that is
> committed to Git (`backend/.env` is already git-ignored).

---

## Part 1 – Database on Neon

1. Open <https://neon.tech> and sign up (the GitHub login is easiest).
2. Click **New Project**.
   - Name: `aashanet`
   - Region: **AWS Asia Pacific (Singapore)** (closest to India)
   - Click **Create project**.
3. On the project dashboard click **Connect**, and copy the connection
   string. It looks like:

   ```text
   postgresql://neondb_owner:xxxxxxxx@ep-xxxx-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

   Keep it somewhere private (for example Notepad, not saved in the project).
   This is your **`DATABASE_URL`**.
4. Create the tables. In Neon open **SQL Editor** and run these three files
   **one at a time, in this order**. For each one: open the file in VS Code,
   select all (Ctrl+A), copy, paste into the SQL Editor, click **Run**.

   1. `backend/migrations/001_create_users.sql`
   2. `backend/migrations/002_create_health_records.sql`
   3. `backend/migrations/003_offline_sync.sql`

   Each should finish without a red error. Run each file only once.

## Part 2 – Backend on Render

The repository already contains `render.yaml`, which tells Render how to
build and start the backend. You only need to give it the two secrets.

1. Make sure your latest code is on GitHub:

   ```powershell
   cd C:\PROJECTS\AASHANet-AI
   git push origin main
   ```

2. Open <https://render.com> and sign up with GitHub.
3. Click **New +** → **Blueprint**.
4. Connect your GitHub account if asked, and pick the **Aashanet** repository.
5. Render reads `render.yaml` and shows one service, `aashanet-backend`.
   It asks for the two secret values:
   - **`DATABASE_URL`** – paste the Neon connection string from Part 1.
   - **`GEMINI_API_KEY`** – paste your key from
     <https://aistudio.google.com/apikey> (the same one as in your local
     `backend/.env`).

   `JWT_SECRET_KEY` is generated by Render automatically.
6. Click **Apply** / **Deploy Blueprint**. The first build takes 3–5 minutes.
   Watch the **Logs** tab; it is done when you see
   `Uvicorn running on http://0.0.0.0:...` and the status shows **Live**.
7. Copy your service address from the top of the page, for example
   `https://aashanet-backend.onrender.com`.
8. Check it works – open these in a browser:
   - `https://aashanet-backend.onrender.com/` → shows
     `"AASHANet AI backend is running"`
   - `https://aashanet-backend.onrender.com/health/database` → reports the
     database is connected
   - `https://aashanet-backend.onrender.com/docs` → the API page

### Create login accounts in the cloud database

The cloud database starts empty, so create the admin and the ASHA worker
accounts. Run this on your PC in **PowerShell**; it uses your local Python
but writes to the Neon database. `$env:DATABASE_URL` only lasts for this
PowerShell window, so your local `.env` is not changed.

```powershell
cd C:\PROJECTS\AASHANet-AI\backend
$env:DATABASE_URL = "PASTE-THE-NEON-CONNECTION-STRING-HERE"
.\.venv\Scripts\python.exe -m scripts.create_admin --role admin
.\.venv\Scripts\python.exe -m scripts.create_admin --role asha_worker
```

Answer the questions (username, full name, password). Close the PowerShell
window afterwards so the cloud address is forgotten.

## Part 3 – Point the phone app at the cloud backend

1. Open `mobile/lib/config.dart` and fill in **`cloudServerUrl`** with your
   Render address (use `https`, no `/` at the end):

   ```dart
   const String cloudServerUrl = 'https://aashanet-backend.onrender.com';
   ```

   To go back to your PC on Wi-Fi later, set it back to `''`.

2. Build the release APK:

   ```powershell
   cd C:\PROJECTS\AASHANet-AI\mobile
   flutter build apk --release
   ```

3. The APK is created at:

   ```text
   C:\PROJECTS\AASHANet-AI\mobile\build\app\outputs\flutter-apk\app-release.apk
   ```

4. Copy it to the phone (USB cable, Google Drive or WhatsApp "Document"),
   tap it, allow **Install unknown apps** when Android asks, and install.
5. Open the app, choose a language, and log in with the ASHA worker account
   you created in Part 2.

## Updating the deployment later

- **Backend change:** commit and `git push origin main`. Render redeploys
  automatically (`autoDeploy: true` in `render.yaml`).
- **Database change:** run the new `backend/migrations/00X_*.sql` file in the
  Neon SQL Editor, *before* pushing the backend code that needs it.
- **App change:** run `flutter build apk --release` again and reinstall the
  new APK (it installs over the old one; records saved on the phone stay).

## Good to know

- **Free Render services sleep** after 15 minutes without requests. The first
  request afterwards takes about 50 seconds. The app may show *Offline* for
  that first minute; records are saved on the phone and sync automatically
  once the server is awake. Before a demo, open the `/` address in a browser
  a minute early to wake it.
- **Audio files** are not kept on the server: each upload is written to a
  temporary file, sent to Gemini, and deleted. The recordings stay on the
  phone, so Render's temporary disk does not lose anything.
- **Neon free plan** pauses the database when idle and wakes it on the next
  connection (a second or two). Its storage (0.5 GB) is far more than the
  text records need.
- **Gemini quota:** the free Gemini API tier has a daily request limit. If
  AI processing starts failing for everyone at once, check the quota at
  <https://aistudio.google.com>.
- **Logs:** Render → `aashanet-backend` → **Logs** shows every request and
  any error, which is the first place to look if something fails.
